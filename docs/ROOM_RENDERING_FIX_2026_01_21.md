# Room Rendering Fix - Depth Calculation
**Date:** January 21, 2026

## Issue Description
The Python rendering routine was producing incorrect occlusion (depth sorting) in generated room images.
Comparison with `debug_trace.txt` from the JavaScript reference implementation revealed that `Depth` values were constant for all tiles generated by a single Block, whereas the Python implementation was calculating depth dynamically per-tile based on screen coordinates.

## Analysis
1.  **Reference Logic:** The `ROOM_GENERATION.md` states:
    > "DEPTHX and DEPTHY are calculated based on the block's geometric center (used for occlusion)."
    This implies depth is a property of the *Block* execution context, not the individual tiles.

2.  **Trace Evidence:** `debug_trace.txt` showed constant depth values for sequences of tiles belonging to the same block.
    -   Block at `(8, 16, H=6)` produced `Depth: -16`.
    -   Block at `(18, 30, H=2)` produced `Depth: 4`.

3.  **Formula Derivation:**
    By comparing the block coordinates (X, Y, Height) with the trace Depth values:
    -   `Block 1`: `8 + 16 + 6 = 30`. `Depth = -16`. Difference = 46.
    -   `Block 2`: `18 + 30 + 2 = 50`. `Depth = 4`. Difference = 46.
    
    This confirmed the formula:
    **`Depth = X + Y + H - 46`**

4.  **Python Issue:** The `graphics.py` module was using a formula `depth = 2*Y + H - 15` calculated per-tile, which ignored the X coordinate's contribution to depth in the isometric projection and varied across the block.

## Fix Implementation
1.  **`src/abadia/graphics.py`**:
    -   Updated `TileBuffer.draw_tile` and `BufferedCanvas.draw_tile_by_id` to accept an explicit `depth` argument.
    -   If `depth` is provided, it bypasses the local calculation.

2.  **`src/abadia/interpreter.py`**:
    -   Updated `AbadiaInterpreter.execute` to accept `height` and calculate `self.current_depth` using the derived formula `X + Y + H - 46` at the start of block execution.
    -   Updated `draw` method to pass this constant `current_depth` to the canvas.

3.  **`src/abadia/room_renderer.py`**:
    -   Updated to extract `height` from `block_entry.extra_param` (defaulting to 0 if None) and pass it to the interpreter.

## Results
All rooms have been re-rendered with the corrected depth logic. This should resolve the occlusion artifacts where background tiles were drawing over foreground tiles or vice-versa.
