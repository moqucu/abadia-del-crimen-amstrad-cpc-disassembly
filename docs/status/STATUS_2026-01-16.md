## 🔍 Investigation: Room Rendering & Reference Comparison

### 1. Room Definition Analysis
- **Goal:** Verify if `ROOM_DEFINITIONS` extracted from `abadia8.bin` matches the known working `rooms.json` from the reference repository.
- **Finding:** A side-by-side comparison of **Room 0** confirmed a **perfect match** in data structure, with two consistent mappings:

    3.  **Height:** Reference `height: 255` corresponds to `extra_param: None` (default).

### 2. Interpreter Logic Verification
- **Goal:** Determine why the rendered output "has missing tiles" / gaps.
- **Analysis:**
    - Analyzed `src/abadia/interpreter.py`.
    - Traced `Block 0x0F` (Floor) execution.
    - **Logic:** The script uses `IncX` and `IncY` to draw diagonal strips.
    - **Result:** On a flat orthogonal grid, this produces a "staircase" pattern: `(0,0), (1,1), (2,2)`.
    - **Issue:** Staircases have gaps between steps `(0,1)` and `(1,0)`. In an **Isometric Projection**, `(1,1)` aligns horizontally with `(0,0)`, closing the gap.
    - **Conclusion:** The interpreter faithfully executes the Z80 logic. The visual "gaps" are an artifact of viewing isometric data on an orthogonal grid without projection.

### 3. Reference Repository Analysis
- **File:** `src/levels/AbadiaBuilder.js` and `src/levels/ScriptInterpreter.js`.
- **Logic:**
    - The reference code draws sprites at `x * 16` and `y * 8` based on a 16x20 tile buffer.
    - It uses a transformation formula `depthx = (y + h/2) + x - 15` / `depthy = ...` which matches the disassembly `1FB8`.
    - However, it appears to execute a high-level script (decompiled) rather than raw Z80, making direct correlation complex.
